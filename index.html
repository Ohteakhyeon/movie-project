Project

영화관 예매 서비스 인프라 구축

React 기반 영화관 예매 서비스를 Web / WAS / DB 구조로 분리하고, VMware Linux 서버 환경과 AWS 클라우드로 확장하는 인프라 포트폴리오입니다.

웹 페이지 제작이 목적이 아니라, 실제 서비스가 운영되는 서버 구조를 이해하고 Web·WAS·DB를 분리하여 구축·운영·장애 대응하는 과정을 중심으로 정리했습니다.

Service Features

서비스 기능

사용자는 영화 목록을 확인하고 좌석을 선택해 예매하며, 데이터는 Express API를 거쳐 MariaDB에 저장됩니다.

  • 영화 목록 조회
  • 영화별 좌석 선택
  • 예매자 이름 입력
  • 좌석 예매 등록
  • 예매 내역 조회
  • MariaDB 예매 데이터 저장
  • 트랜잭션 기반 좌석 중복 예매 방지

Current Architecture

현재 아키텍처

사용자 브라우저
   ↓
React + Vite Web
   ↓
Node.js Express API
   ↓
MariaDB
Tier Role Technology

WAS API 처리 및 예매 로직 수행 Node.js, Express

VMware 3-Tier Plan

VMware 배포 계획

Rocky Linux 서버 3대로 실제 운영과 유사한 Web / WAS / DB 구조를 구축합니다.

사용자 브라우저
   ↓
web01 — Nginx / React Build
   ↓
was01 — Node.js Express API
   ↓
db01  — MariaDB
Server Role Main Components
web01 Web Server Nginx, React Build
was01 WAS Server Node.js, Express, systemd
db01 DB Server MariaDB
  • 01Rocky Linux VM 3대 생성
  • 02고정 IP 및 hostname 설정
  • 03Nginx 정적 파일 배포
  • 04Nginx Reverse Proxy 설정
  • 05Node.js API systemd 서비스 등록
  • 06MariaDB DB 생성 및 계정 권한 설정
  • 07firewalld 포트 제어
  • 08Web → WAS → DB 통신 검증
AWS 3-Tier Plan

AWS 클라우드 확장

VMware에서 검증한 구조를 Public / Private Subnet으로 분리해 AWS에 확장합니다.

Internet
   ↓

   ↓

   ↓
Private Subnet
   ↓
WAS EC2 — Node.js Express
   ↓

  • 04EC2 기반 Web / WAS / DB 서버 구성
  • 05Security Group 기반 접근 제어
  • 06Web 서버만 외부 접근 허용
  • 07WAS·DB는 Private Subnet 배치
  • 08Web → WAS → DB 방향만 통신 허용
Operation Plan

운영 계획

systemd로 서비스 상태를 관리하고, 로그·네트워크로 장애 원인을 분석합니다.

  • —Nginx 서비스 자동 시작
  • —Node.js API systemd 등록
  • —MariaDB 자동 시작
  • —서버 간 포트 통신 확인
  • —API Health Check
  • —예매 데이터 DB 저장 확인
  • —로그 기반 장애 분석

Troubleshooting

장애 대응 계획

운영 장애를 재현하고, 원인 분석·복구 과정을 문서화합니다.

장애 1. WAS 서비스 중지

상황
웹 페이지에서 API 호출 실패 또는 502 Bad Gateway
원인
was01의 Node.js Express 서비스 중지
확인
Nginx error.log, systemctl status movie-api
조치
movie-api 서비스 재시작
검증
/api/health 및 /api/movies 정상 응답 확인

장애 2. DB 연결 실패

상황
예매 등록 시 DB 저장 실패
원인
MariaDB 서비스 중지 또는 DB 접근 불가
확인
journalctl, systemctl status mariadb, nc -zv db01 3306
조치
MariaDB 재시작 또는 방화벽 설정 수정
검증
reservations 테이블에 예매 데이터 저장 확인

장애 3. 방화벽 / Security Group 차단

상황
Web → WAS 또는 WAS → DB 통신 실패
원인
firewalld 또는 AWS Security Group 규칙 누락
확인
curl, nc, firewall-cmd, Security Group 인바운드 규칙
조치
필요한 포트만 허용하도록 규칙 수정
검증
Web → WAS → DB 통신 정상 확인
Roadmap

확장 로드맵

  1. 로컬 Web / WAS / DB 개발 환경에서 3-Tier 구조 구현 및 기능 검증

  3. AWS 클라우드 3-Tier VPC·Subnet·Security Group 기반 인프라 확장

  5. Kubernetes 컨테이너 기반 운영으로 확장
Expected Result

기대 성과

단순한 웹 서비스 구현을 넘어, 실제 서비스 운영에 필요한 인프라 구성과 운영 흐름을 경험하는 것이 목표입니다.

Linux 서버 운영, Nginx Reverse Proxy, Node.js systemd 관리, MariaDB 연동, 방화벽, AWS 네트워크, 장애 대응을 단계적으로 정리했습니다.
